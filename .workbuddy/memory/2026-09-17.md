# 2026-09-17 · 修复 index.html 的 favicon 语法错误

## 现象
parse5 报 3 条错（均在 `index.html:5`）：
```
index.html:5:128  missing-whitespace-between-attributes
index.html:5:150  unexpected-character-in-attribute-name
index.html:5:152  non-void-html-element-start-tag-with-trailing-solidus
```

## 根因
**页面编辑器把 `data-page-node-id` 注入到了 favicon 的 `data:` URI 内部**，
而且用的是**双引号**：

```html
<link rel="icon" href="data:image/svg+xml,<svg … data-page-node-id="IT2Ck…"><rect … ></svg>" />
                                                                            ↑ href 在这里就被提前闭合了
```

`href="…"` 在第一个嵌套双引号处闭合，剩下的 `IT2Ckz5T0RQV7viYtzvAEp"` 被当成新属性名，
于是「属性之间缺空格」+「属性名里有非法字符」一起爆出来。
裸 `<` `>` 也让 URI 本身不合法。

## 修法
把 SVG 整体做 **URL 编码**写进 `data:` URI（只改 `index.html` 第 5 行）：

```html
<link rel="icon" href="data:image/svg+xml,%3Csvg%20xmlns='http://www.w3.org/2000/svg'%20viewBox='0%200%20100%20100'%3E%3Crect%20width='100'%20height='100'%20rx='10'%20fill='%230078D4'/%3E%3Ctext%20y='70'%20x='50'%20text-anchor='middle'%20font-size='60'%3E%E2%98%95%3C/text%3E%3C/svg%3E" />
```

编码要点：`<`→`%3C`、`>`→`%3E`、`#`→`%23`、空格→`%20`、
emoji `☕`(U+2615) → `%E2%98%95`；属性值外层用**单引号**包 SVG 内部属性，
既避开双引号冲突、单引号本身也是 RFC 3986 合法 sub-delim。

## 验证
- `parse5`（`node_modules` 里随 jsdom 带进来，可直接 `require('parse5')`）
  复检 `index.html`：**3 errors → 0 errors** ✅
- `decodeURIComponent` 解码 URI，与原始 SVG **逐字符相等**（同一只咖啡杯，视觉零变化）✅
- URI 内无裸 `<` `>` `"` `#` ✅
- `npx vite build` 重建后 `build/index.html` 同样 0 errors ✅

## 顺手记下的工具
临时脚本 `_html-check.mjs`（parse5 + `onParseError` 打印 `行:列 错误码`）
已删除；需要时重写只要几行——`parse5` 已在依赖树里，不用装包。
**这类问题 tsc / vitest 都拦不住**（不解析 .html），
所以编辑器报 HTML 语法错时，用 parse5 做一次 `onParseError` 复检是最快的闭环。

# 2026-09-17 · 「自定义接入」新增自动解析接入（上传 JSON 文件）

## 任务
> 「在接入数据源中的自定义接入功能里面加入一个自动解析接入的功能，
> 场景对应的是用户上传一个 json 文件可以自动解析里面的内容接入数据源」

## 核心设计决策：本地文件用 `localRows`，不用 data: URL

第一反应是把文件内容编码成 `data:application/json;base64,...` 塞进 `endpoint.url`，
这样 `fetch()` 天然支持、下游零改动。**放弃了这个方案**，原因：

- base64 体积膨胀 ~33%，且每次渲染都要算这个大字符串；
- 已接入列表会把这个巨型 URL 打印出来，界面直接崩坏；
- `datasetFetcher` 里已经有 `pickRows` 这层解析口径，走内存行反而是同一条路径。

改成在 `DataEndpoint` 上加两个字段：
`localRows?: Record<string, unknown>[]` + `localFileName?: string`，
`fetchEndpointRows` 见到 `localRows` **直接返回、不发请求** ——
于是「离线可用 / 不受 CORS 限制」是免费得到的，`InstanceBrowser` 与
`AIQueryConsole` 一行都不用改就支持了本地数据源。

**关键前提**：`endpoints` 本来就**没有持久化**（只在内存，来自 `buildDefaultEndpoints()`），
所以存整份行数据不会撞 localStorage 配额。刷新后需要重新上传，
与「手动添加的自定义数据源也会丢」的既有行为一致。

## 分层：解析逻辑全在纯函数里
`src/lib/jsonAutoImport.ts`（新增）：
`normalizeKey` / `collectColumns` / `guessEntityType` / `autoMapColumns` /
`parseJsonForImport` / `readFileAsText`，**不碰 DOM**，所以 25 条测试全部是纯函数级。

识别算法：
- 列名归一化（去 `_ - . 空格`、NFKC、小写）→ `customer_id` ≡ `customerId`；
- 命名匹配：完全同名 3 分 / 包含关系 1.5 分 / 主键列额外 +1；
- **实体识别有门槛**：至少命中 2 列且累计 ≥4 分，达不到就 `null` 交给用户选；
- 列映射按分数降序**贪心分配**，一个属性只被一列占用（避免两列抢同一属性）。

## 顺手修掉的两个真 bug
1. **`pickRows` 不认识 `{ data: [...] }`** —— 只处理了 `results` 数组和
   `data.某字段` 为数组两种情况，`{ data: [ ... ] }` 这种很常见的 REST 响应
   会被整包当成「一行」，列名变成 `data`。已补 `Array.isArray(obj.data)` 分支。
2. **jsdom 的 `File` 没有 `.text()`** —— 组件里用 `await file.text()` 会导致
   「浏览器能跑、测试必崩」的两套代码路径。改成统一走 `FileReader`
   （`readFileAsText`），浏览器与 jsdom 行为一致。
   实测：`typeof f.text === 'undefined'`、`typeof FileReader === 'function'`。

## 界面
「自定义接入」展开后分两段：**自动解析接入**（虚线投放区 → 预览 → 接入）
＋ 分隔线「或手动填写」＋原有表单。
预览里实体下拉一改，列映射**实时重算**（`autoMappings` 是 `useMemo` 派生值，
不是 state —— 存 state 就得在 onChange 里手动同步，必漏）。
已接入列表里本地数据源显示「本地文件」标签 + `文件名 · N 行`，不再显示 `local://` 链接。

- `npx vitest run` → **32 文件 / 612 测试全绿**（+36）
