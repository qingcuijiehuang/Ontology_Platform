## 关键设计取舍
- **不引入 OpenAI SDK** —— 端点格式是 OpenAI 兼容，行业基本统一，
  浏览器原生 fetch + SSE 解析足够，省体积、可控。
- **浏览器直连 CORS** —— 实测 openai/deepseek/zhipu/dashscope/moonshot/
  siliconflow 全部支持跨域（无需代理）。ollama/custom 给出可选
  `proxyBaseUrl` 字段，前端会拼前缀（如 `http://localhost:8787/v1/...`），
  适合自建反代/网关。
- **不强制流式** —— 流式在大模型厂商几乎都支持，但降级路径（fetch() 解析
  全文）也保留，老浏览器/代理不稳定时自动走非流式。
- **没有让 AI 编造** —— 系统 prompt 明确要求"当本体和数据不足以回答时
  也要明确告知"，并要求"标注依据"，给出"数据集引用 / 实体命中 chips"
  这种可点击依据。
- **隐私** —— Key 存浏览器 localStorage，外部数据不经我们后端；唯一风险
  是用户直接部署的页面在公网被访问（参考 `DEFAULT_LLM_CONFIG`/`memory`
  中的部署注意事项）。

## 检索召回升级（2026-09-13 晚）

背景：用户反馈图谱高亮不工作 + 误以为「取前 8 行」是按问题召回。

**根因 1**：`processQuery` 的 `scoreMatch` 只在英文实体名/描述/属性名上做 token 重合，
中文问题（"客户"、"订单"、"Platinum 会员" 等）几乎全部 0 命中 → highlightEntities 为空 → 图谱不亮。

**根因 2**：`buildDatasetContext` 用 `ds.rows.slice(0, rowsPerDataset)` 直接切片前 N 行，
没有任何相关性打分 → 用户预期的"按问题召回"实际不存在。

**改动**：
- `src/data/ontology.ts`：EntityType 加 `synonyms?: string[]`，给 6 个实体填入中英文同义词。
- `src/data/queryEngine.ts`：
  - 新增 `ENTITY_ALIASES` / `RELATIONSHIP_ALIASES` 兜底表；
  - 新增 `tokenize(text)`（英文按词 + 中文单字 + bigram + 停用词）；
  - 新增 `tokenOverlapScore` / `bestHaystackMatch`；
  - 新增 `selectRelevantRows(rows, question, mappings, topN, {minKeep, maxCellChars})`；
  - 实体/关系打分改用 `bestHaystackMatch`；
  - `findEntityByName` 也走同义词（让 "X 关联到 Y" 也能用中文）。
- `src/lib/llmClient.ts`：
  - `buildDatasetContext` 接受 `question` 参数，未提供时退化原始顺序；
  - `buildChatMessages` 默认 `rowsPerDataset=16`；
  - 元信息标注「按问题相关性排序」/「原始顺序」。
- `src/components/AIQueryConsole.tsx`：`FETCH_ROWS=50`、`ROWS_PER_ENDPOINT=16`、
  `MAX_ENDPOINTS=6`，上限最高 96 行/提问。

**验证**：tsc ✅、vitest 全量 506/507（剩下 1 个 catalogue 子进程偶发超时，与改动无关）、
vite build ✅、`verify-retrieval-2026-09.mjs` 24/24 ✅。

### 新增：`src/hooks/usePanelResize.ts`（通用 hook，~295 行）
- 基于 Pointer Events + `setPointerCapture`：鼠标 / 触屏 / 触控笔统一处理，
  指针拖出元素甚至拖出窗口也不会丢事件。
- 选项 `{ storageKey, initial, min, max: number | (()=>number), axis:'x'|'y',
  reverse?, step?, resolveStartSize?, label? }`：
  - `max` 支持函数以便按视口动态计算；
  - `reverse` 让面板位于拖动轴正向一侧时（左/下为正向，对应右栏宽度与控制台高度），
    拖动方向与尺寸变化方向相反；
  - **`resolveStartSize` 是关键修复**：面板处于「内容自适应」状态下，
    配置里的 `initial` 未必等于实际渲染尺寸。没有这层，**第一次按下就会先跳一段**
    （被 `clamp` 收敛到 `min` 或 `initial`），体验非常糟。传一个量真实 DOM 的回调
    进来即可解决，测出的尺寸直接当起点。
- 通过 `localStorage` 持久化（key 前缀 `wb_panel_size_`），读取时校验「有限正数」，
  脏值回落 `initial`；用户没调过时 `customized=false`，消费方可以决定
  「没调过 → auto 高度，调过 → 固定尺寸」，避免出现「页面被 360px 卡死」。
- 拖动期间锁 `body.style.userSelect='none'` + `cursor=col/row-resize`，
  离开才自动恢复，避免拖出一片蓝色选区。
- 双击复位 + Tab 聚焦方向键微调 + `role="separator"` + `aria-valuemin/max/now`，
  完整无障碍。
- **调用链严格单向**：hook 只管尺寸状态，不感知任何业务渲染，
  避免与组件已有的 `refreshAll` 入口形成互调环（呼应小台铁律 9）。

### 沉淀的工程约定
1. **可拖动面板的 hook 必须支持 `resolveStartSize`** ——
   任何让面板处于「内容自适应」状态的设计（比如「没调过 → auto」）
   都会导致 `initial` 跟实际渲染尺寸不一致，没有这一层，第一次按下就会跳。
2. **`reverse` 是面板在正向一侧时的默认**。右栏、下方面板都属于「正向一侧」，
   传 `reverse:true` 之后，方向键 / 鼠标方向才会符合直觉
   （向右拖 = 右栏变大，向上拖 = 控制台变大）。
3. **`ResizeObserver` 是图谱 / 画布类组件的标配**：面板尺寸变化时不发 resize，
   图谱会留在旧尺寸。
4. **持久化的尺寸必须校验「有限正数」**（脏值 / `null` / `0` 都算无效），
   否则会把面板拖成 0 不可恢复。
5. 通用拖动 hook **只管尺寸状态、不感知业务渲染**，
   避免与组件已有的 `refreshAll` 入口互调成环。
