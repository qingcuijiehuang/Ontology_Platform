# 2026-09-14 — 修复「导入 RDF 报 No ontology metadata or OWL classes found」

## 用户报错
在「导入 / 导出本体」弹窗里上传 .rdf 文件后失败：
```
RDF 解析错误：No ontology metadata or OWL classes found in the RDF document.
```

## 根因（两层）
1. **只认一种 RDF/XML 写法**。`parseRDF`（`src/lib/rdf/parser.ts`）用
   `root.getElementsByTagNameNS(OWL_NS, 'Class')` 精确匹配命名空间 + local name，
   于是 **只有** `<owl:Class rdf:about="…">` 这一种形态能被识别。
2. **`getElementsByTagNameNS` 不包含调用元素自身**，因此「根元素就是 `<owl:Ontology>`」
   （没有 `<rdf:RDF>` 包裹）的文档一个元素都找不到。

## 诊断方法（值得复用）
先造 8 种常见 RDF/XML 变体做成临时测试跑一遍，精确定位哪些挂了：

| 变体 | 修复前 | 修复后 |
| --- | --- | --- |
| A. `<owl:Class rdf:about>`（本项目导出格式） | ✅ | ✅ |
| B. `rdf:Description` + `rdf:type owl:Class`（工具/数据库导出常见） | ❌ | ✅ |
| C. 根元素直接是 `<owl:Ontology>` | ❌ | ✅ |
| D. 旧式 owl 命名空间（`…/owl` 无 `#`） | ❌ | ✅ |
| E. 默认命名空间（`xmlns=` 指向 owl） | ✅ | ✅ |
| F. Turtle 内容 | ❌ 报 Malformed XML | ⛔ 明确「请转成 RDF/XML」指引 |
| G. `rdfs:Class`（RDFS 本体） | ❌ | ✅ |
| H. 只有实例（NamedIndividual），没有类 | ❌ 报同一句 | ⛔ 明确「这是实例数据不是本体」 |

## 修复内容
`src/lib/rdf/parser.ts`（核心）：
- **命名空间归一化** `normalizeNs()`：统一 `https→http` + 去掉结尾 `#`/`/`，
  旧式 `http://www.w3.org/2002/07/owl` 与标准 `…#` 视为同一个。
- **自写 `walk()`** 深度遍历，**含 root 自身**，替代 `getElementsByTagNameNS`。
- **`getTypeUris()` / `hasType()`**：解析 `rdf:type`，
  从而支持 `<rdf:Description><rdf:type rdf:resource="…#Class"/></rdf:Description>`。
- **收集器拆成三个**：`collectOntologyElements` / `collectClassElements`
  （OWL + RDFS 的 Class）/ `collectPropertyElements`，每个都同时走
  「显式标签」与「rdf:type 声明」两条路，用 `Set` 去重。
- **`getAbout()`** 兼容 `rdf:about` 与 `rdf:ID`。
- **格式体检** `looksLikeJsonLd()` / `looksLikeTurtle()`：在 DOMParser 之前拦截，
  换成用户能照着做的中文提示；`parsererror` 与「找不到本体」两条路径也补了中文说明。
- **`countIndividuals()`**：0 类但有实例时，明确告诉用户「这是实例数据，不是本体」。

`src/components/ImportExportModal.tsx`：
- 扩展名分支补 `.ttl/.n3/.nt/.trig/.nq` 与 `.jsonld` 的专门提示。
- `isXmlContent` 从「`<?xml` / `<rdf:RDF` 开头」放宽为「任何 `<` 开头」，
  否则以 `<owl:Ontology` 开头的文件会被误判成「不支持的文件格式」。
- 先 `replace(/^\uFEFF/,'')` 再去判断，避免带 BOM 的 UTF-8 文件翻车。
- **解析成功但 0 个类**时不再静默导入空图谱，改为提示 + 不上报状态。
- 导入区文案补一行「兼容 owl:Class / rdfs:Class，以及 rdf:Description + rdf:type 两种写法」。

## 沉淀的工程约定
1. **解析外部文件时要「宽容输入、严格输出」**。
   同一份标准的多种合法序列化写法（显式标签 vs `rdf:type` 声明）都必须吃下，
   不能只认自家导出器产出的那一种形态。
2. **命名空间比较一律先归一化**（`https→http`、去尾部 `#`/`/`），
   再谈相等；直接用 `===` 比字符串会漏掉大量历史文件。
3. **遍历要用自写的 `walk`（含根元素）**，不要指望 `getElementsByTagNameNS`
   —— 它不返回调用元素自身。
4. **报错要指向下一步动作**。把「Malformed XML」这类开发者语言，
   换成「你这是 Turtle 语法，请在 Protégé 里另存为 RDF/XML」，
   用户才知道该做什么。
5. **别静默成功**。解析出 0 个类却当作导入成功，用户看到的是空白图谱，
   比直接报错更让人困惑。
